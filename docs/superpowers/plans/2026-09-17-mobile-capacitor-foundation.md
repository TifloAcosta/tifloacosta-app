# TifloAcosta Mobile Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert the existing TifloAcosta web app into a Capacitor-based mobile project, with Android ready first for closed testing and the same foundation prepared for iOS.

**Architecture:** Keep the current accessible static web app as the single source of truth. A deterministic mobile build script copies only runtime assets into `www/`; Capacitor wraps that build with application id `com.tifloacosta.app` and app name `TifloAcosta`. Android is generated and verified first; iOS remains enabled in the dependency/configuration layer for the next phase on macOS/Xcode.

**Tech Stack:** Existing HTML/CSS/JavaScript app, Node.js test runner, Capacitor 8.5.2, Android/Gradle generated by Capacitor, GitHub Actions.

**Spec:** This plan implements the mobile-store direction agreed in chat: one shared TifloAcosta core, Android first to start the closed-testing clock, then iOS using the same Capacitor foundation.

## Global Constraints

- Preserve the current web deployment and its accessible navigation.
- Use application id `com.tifloacosta.app` on Android and iOS unless a store collision forces a later change.
- Use app name `TifloAcosta`.
- Use Capacitor 8.5.2 consistently for core, CLI, Android and iOS packages.
- `www/`, native build outputs, signing files and keystores must not become public source artifacts.
- No signing secret, password or private key may be committed to the repository.
- Android must be buildable in CI without changing production web behavior.
- Existing `npm test` regression coverage must continue to pass.
