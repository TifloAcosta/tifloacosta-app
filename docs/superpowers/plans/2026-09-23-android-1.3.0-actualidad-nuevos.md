# Android 1.3.0 Actualidad New Items Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Actualidad tell users which news items appeared since their previous visit without turning the section into a full read/unread inbox.

**Architecture:** Store one local baseline of stable news IDs. Compare the current catalog against that baseline when content loads, pass the resulting new-ID set into the Actualidad renderer, and mark the current catalog seen after the first render of that visit so the same items are not announced again on the next visit.

**Tech Stack:** JavaScript ES modules, localStorage-compatible storage, Node 22 test runner, existing `mobile-content.json` news catalog and `renderActualidad` screen.

**Spec:** `docs/superpowers/specs/2026-09-23-android-1.3.0-design.md`

## Global Constraints

- Use stable news IDs, never titles, as identity.
- Keep state local to the device; no accounts, server state, analytics, or cloud sync.
- First use establishes a baseline and reports zero new items.
- Later items absent from the stored baseline are new until Actualidad is visited.
- Visiting Actualidad marks the current catalog seen for the next visit, but the current render still shows the markers that brought the user there.
- New-state must work with fresh or cached content.
- Accessible markers must be text, not color or icons alone.
- Add Spanish and English copy together.
- Do not introduce per-article manual read/unread controls.

## Review Focus

- Duplicate or blank IDs must not create false counts or corrupt the baseline.
- A damaged localStorage value must behave like first use rather than crashing the app.
- Cached content must be compared exactly like fresh content.
- Re-rendering the same Actualidad visit must not multiply counters or duplicate `Nuevo` text.
- A second visit with no intervening new catalog IDs must report zero new items.

test('first comparison establishes baseline without declaring backlog new', () => {
  const storage = memoryStorage();
  const store = createNewsSeenStore(storage);
  assert.deepEqual([...store.compare(items('a', 'b'))], []);
  assert.deepEqual([...store.readBaseline()].sort(), ['a', 'b']);

test('later unseen IDs remain new until markSeen', () => {
  const storage = memoryStorage({ [NEWS_SEEN_KEY]: JSON.stringify(['a', 'b']) });
  const store = createNewsSeenStore(storage);
  assert.deepEqual([...store.compare(items('c', 'b', 'a'))], ['c']);
  assert.deepEqual([...store.compare(items('c', 'b', 'a'))], ['c']);
  assert.equal(store.markSeen(items('c', 'b', 'a')), true);

test('duplicate and blank IDs do not create false new items', () => {

- [ ] **Step 3: Implement the minimal store**

Create `mobile/src/core/news-seen.mjs`:

```js
export const NEWS_SEEN_KEY = 'tiflo-mobile-news-seen-v1';

function stableIds(items) {
  const ids = [];
  const seen = new Set();
  for (const item of Array.isArray(items) ? items : []) {
    const id = String(item?.id || '').trim();
    if (!id || seen.has(id)) continue;
    seen.add(id);
    ids.push(id);
  }
  return ids;
}

export function createNewsSeenStore(storage = globalThis.localStorage) {
  function readRaw() {
    if (!storage || typeof storage.getItem !== 'function') return null;
    try {
      const parsed = JSON.parse(storage.getItem(NEWS_SEEN_KEY));
      return Array.isArray(parsed) ? new Set(parsed.map(value => String(value || '').trim()).filter(Boolean)) : null;
    } catch {
      return null;
    }
  }

  function write(ids) {
    if (!storage || typeof storage.setItem !== 'function') return false;
    try {
      storage.setItem(NEWS_SEEN_KEY, JSON.stringify([...ids]));
      return true;
    } catch {
      return false;
    }
  }

  function compare(items) {
    const current = new Set(stableIds(items));
    const baseline = readRaw();
    if (!baseline) {
      write(current);
      return new Set();
    }
    return new Set([...current].filter(id => !baseline.has(id)));
  }

  function markSeen(items) {
    return write(new Set(stableIds(items)));
  }

  function readBaseline() {
    return readRaw() || new Set();
  }

  return { compare, markSeen, readBaseline };
}
```
