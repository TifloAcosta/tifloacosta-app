# Android 1.3.0 Integration and Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate the three Android 1.3.0 feature plans, verify them together, bump the Android package to versionName 1.3.0/versionCode 8 only after feature verification, and produce a signed closed-beta AAB while keeping physical notification validation explicitly pending.

**Architecture:** Implement notifications, Actualidad new-state, and version information on one isolated feature branch from current `main`, resolving their shared `app.mjs`, `settings.mjs`, and `i18n.mjs` edits through tests rather than manual guesswork. Only after all feature suites and the full mobile suite pass should release metadata move from 1.2.0/7 to 1.3.0/8 and the signed Android workflow be allowed to produce the release artifact.

**Tech Stack:** Git/GitHub, Node 22, Capacitor 8.5.2, Android Gradle, GitHub Actions, existing Android signing secrets, OneSignal Capacitor SDK 1.1.6.

**Spec:** `docs/superpowers/specs/2026-09-23-android-1.3.0-design.md`

## Global Constraints

- Implement and verify these plans before version bump:
  - `docs/superpowers/plans/2026-09-23-android-1.3.0-notifications.md`
  - `docs/superpowers/plans/2026-09-23-android-1.3.0-actualidad-nuevos.md`
  - `docs/superpowers/plans/2026-09-23-android-1.3.0-version-info.md`
- Target release is `versionName "1.3.0"`, `versionCode 8`.
- Do not bump version metadata while any feature test is red.
- Keep the release in Google Play closed testing; do not move to production as part of this plan.
- Physical Android validation is pending and is not a blocker for implementation, signed AAB generation, or preparing/publishing the closed-test beta.
- Never state that real push delivery has been verified on hardware until Tony has an Android device and that test is actually performed.
- Preserve existing Share, bounded web fetch, accessible reader, downloads, and video behavior.
- Keep `ONESIGNAL_DISABLE_LOCATION=true` during sync/build.

## Review Focus

- Shared edits to `mobile/src/app.mjs` must preserve initialization order for Share, router, content load, Actualidad new-state, app info, and notification cold-start routing.
- Shared edits to `mobile/src/core/i18n.mjs` must retain complete ES/EN keys for both new Actualidad copy and app-information copy.
- Shared edits to `mobile/src/screens/settings.mjs` must render Notifications and App information exactly once and must not introduce autofocus.
- Version/build shown in Settings must still come from `App.getInfo()`, not the release test or hard-coded copy.
- A green CI run must not erase the explicit “physical notification validation pending” status.

### Task 3: Add one cross-feature integration guard for shared files

**Files:**
- Create: `mobile/test/android-1.3.0-integration.test.mjs`
- Read: `mobile/src/app.mjs`
- Read: `mobile/src/screens/settings.mjs`
- Read: `mobile/src/core/i18n.mjs`

**Interfaces:**
- Produces: one test that catches accidental overwrite/loss when the three feature plans modify shared files.

- [ ] **Step 1: Write the integration guard**

Create `mobile/test/android-1.3.0-integration.test.mjs`:

```js
import assert from 'node:assert/strict';
import { readFile } from 'node:fs/promises';
import test from 'node:test';

const read = path => readFile(new URL(`../${path}`, import.meta.url), 'utf8');

test('1.3.0 shared app wiring keeps all three feature families', async () => {
  const app = await read('src/app.mjs');
  assert.match(app, /createOneSignalNotifications/);
  assert.doesNotMatch(app, /createNotificationService\(null\)/);
  assert.match(app, /createNewsSeenStore/);
  assert.match(app, /createAppInfoService\(App\)/);
});

test('1.3.0 Settings keeps notification controls and app information together', async () => {
  const settings = await read('src/screens/settings.mjs');
  assert.match(settings, /addNotificationSettings/);
  assert.match(settings, /addAppInfoSettings/);
  assert.match(settings, /aria-live/);
  assert.doesNotMatch(settings, /autofocus/i);
});

test('1.3.0 bilingual copy contains notification, Actualidad and app-info keys', async () => {
  const i18n = await read('src/core/i18n.mjs');
  for (const key of ['notifications', 'newLabel', 'newCount', 'appInfoTitle', 'appVersion', 'appBuild']) {
    assert.match(i18n, new RegExp(key));
  }
});
```

- [ ] **Step 2: Run it**

```bash

node --test test/android-1.3.0-integration.test.mjs
```

Expected: PASS because all three feature plans have been implemented. If RED, fix the shared-file integration rather than weakening the test.

- [ ] **Step 3: Commit**

```bash

git commit -m "test: protect Android 1.3.0 integrated features"
```

### Task 4: Bump Android release metadata to 1.3.0 code 8 last

**Files:**
- Modify: `mobile/android/app/build.gradle`
- Rename/replace: `mobile/test/android-1.2.0-release.test.mjs` -> `mobile/test/android-1.3.0-release.test.mjs`

**Interfaces:**
- Produces: Android package release metadata consumed by `App.getInfo()` and Google Play.

- [ ] **Step 1: Rename the release test and make it fail for the old build**

Rename the file and replace the version test with:

```js
import assert from 'node:assert/strict';
import { readFile } from 'node:fs/promises';
import test from 'node:test';

const read = path => readFile(new URL(`../${path}`, import.meta.url), 'utf8');

test('Android release candidate is version 1.3.0 code 8', async () => {
  const gradle = await read('android/app/build.gradle');
  assert.match(gradle, /versionCode\s+8/);
  assert.match(gradle, /versionName\s+"1\.3\.0"/);
  assert.doesNotMatch(gradle, /versionCode\s+7/);
  assert.doesNotMatch(gradle, /versionName\s+"1\.2\.0"/);
});

test('release candidate keeps native Share and bounded web fetch plugins', async () => {
  const manifest = await read('android/app/src/main/AndroidManifest.xml');
  const mainActivity = await read('android/app/src/main/java/com/tifloacosta/app/MainActivity.java');
  assert.match(manifest, /android\.intent\.action\.SEND/);
  assert.match(manifest, /android:mimeType="text\/plain"/);
  assert.doesNotMatch(manifest, /SEND_MULTIPLE/);
  assert.match(mainActivity, /registerPlugin\(TifloSharePlugin\.class\)/);
  assert.match(mainActivity, /registerPlugin\(TifloWebFetchPlugin\.class\)/);
});
```
