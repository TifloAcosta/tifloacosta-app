# Android 1.3.0 Version Information Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show the installed Android version name and build/versionCode in Settings using native package metadata.

**Architecture:** Wrap Capacitor `App.getInfo()` in a small failure-safe service, inject that service into Settings, and render version/build as ordinary accessible text. The screen never hard-codes `1.3.0` or `8`; release metadata remains owned by Android Gradle.

**Tech Stack:** Capacitor App plugin 8.1.1, JavaScript ES modules, Node 22 test runner, Android Gradle package metadata.

**Spec:** `docs/superpowers/specs/2026-09-23-android-1.3.0-design.md`

## Global Constraints

- Display values from installed native metadata, not duplicated release strings in the UI.
- Show at least `version` and `build`.
- Keep the information in Settings as plain readable text.
- Do not autofocus or announce the block repeatedly through a live region.
- Add Spanish and English strings together.
- Failure to read native metadata must not break Settings.

## Review Focus

- `App.getInfo()` rejection must not cause an unhandled promise rejection.
- Empty or missing `version`/`build` fields must show the unavailable message instead of misleading blanks.
- Opening Settings repeatedly must not duplicate sections.
- The displayed build must come from native metadata, so Android versionCode changes are reflected automatically.
- Web/unit-test environments without a native App plugin must remain usable.

- [ ] **Step 3: Implement the service**

Create `mobile/src/native/app-info.mjs`:

```js
const unavailable = () => ({ available: false, version: '', build: '' });

export function createAppInfoService(appPlugin) {
  return {
    async getInfo() {
      if (!appPlugin || typeof appPlugin.getInfo !== 'function') return unavailable();
      try {
        const info = await appPlugin.getInfo();
        const version = String(info?.version || '').trim();
        const build = String(info?.build || '').trim();
        return version && build
          ? { available: true, version, build }
          : unavailable();
      } catch {
        return unavailable();
      }
    }
  };
}
```

- [ ] **Step 4: Add the Settings section**

In `mobile/src/screens/settings.mjs`, add:

```js
function addAppInfoSettings(root, appInfoService, t) {
  const section = document.createElement('section');
  section.className = 'settings-section app-info';

  const heading = document.createElement('h2');
  heading.textContent = t('settings.appInfoTitle');
  section.append(heading);

  const details = document.createElement('div');
  section.append(details);
  root.append(section);

  void (async () => {
    const info = await appInfoService.getInfo();
    details.replaceChildren();
    if (!info.available) {
      const unavailable = document.createElement('p');
      unavailable.textContent = t('settings.appInfoUnavailable');
      details.append(unavailable);
      return;
    }

    const version = document.createElement('p');
    version.textContent = t('settings.appVersion').replace('{version}', info.version);
    const build = document.createElement('p');
    build.textContent = t('settings.appBuild').replace('{build}', info.build);
    details.append(version, build);
  })();
}
```

Change the renderer signature to include the service:

```js
export function renderSettings({
  root,
  router,
  preferences,
  notificationService,
  appInfoService,
  t,
  onPreferencesChange
}) {
```

Call `addAppInfoSettings(root, appInfoService, t)` once near the end of Settings, after normal preference controls and before or after Notifications consistently.
