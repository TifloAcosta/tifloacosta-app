# Android 1.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Android 1.3.0 with a real OneSignal notification adapter, useful notification routing, local “new in Actualidad” tracking, and accessible installed-version information.

**Architecture:** Keep OneSignal isolated behind the existing notification service abstraction, add a pure notification-destination resolver, add a separate local seen-state store for Actualidad, and pass native app metadata into Settings. Reuse the existing reader, video, resource and download flows instead of duplicating navigation logic.

**Tech Stack:** Node 22 tests, ES modules, Capacitor 8.5.2, `@capacitor/app` 8.1.1, `@onesignal/capacitor-plugin` 1.1.6, Android Gradle app, esbuild.

**Spec:** `docs/superpowers/specs/2026-09-23-android-1.3.0-design.md`

## Global Constraints

- Do not request notification permission automatically at app startup.
- The user must trigger permission from Settings > Notifications.
- Keep Spanish and English strings in sync.
- Notification routing must reuse existing accessible flows.
- Invalid/stale notification data must fall back safely to Home.
- New-state for Actualidad remains local only; no accounts or server tracking.
- Do not depend on color alone for “Nuevo”.
- No autoplay, autofocus, repeated focus jumps, or TalkBack-specific behavior.
- `versionName` becomes `1.3.0`; `versionCode` becomes `8` only after feature verification.
- Lack of a physical Android device does not block code completion or AAB generation; physical notification validation remains explicitly pending.

## Review Focus

- OneSignal initialized but permission still never requested until the user presses the button.
- Notification click arrives before router/content startup and is processed exactly once after readiness.
- Malformed or obsolete notification payload cannot navigate to a broken state.
- Corrupt/blocked local storage does not make Actualidad crash or repeatedly mark everything new.
- Native version metadata failure does not break Settings; it degrades to unavailable text rather than hard-coded false data.
