# Mi Música Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a personal accessible music library and player to TifloAcosta iOS and Android with optional cloud sources and backups.

**Architecture:** A platform-neutral catalog and playlist model uses source adapters instead of physical file paths as identities. Native iOS and Android layers implement storage permissions, playback/equalization and background tasks independently; cloud adapters use scoped authentication and expose a common file interface.

**Tech Stack:** JavaScript ESM for shared domain rules and node:test; Swift native iOS (`ios-app-native`); Kotlin Android (`android-native-prototype`); provider SDKs only after verifying current restrictions.

**Spec:** `docs/superpowers/specs/2026-11-17-mi-musica-design.md`

## Global Constraints

- Visible section name: `Mi Música`.
- Never mutate source files when editing virtual folders/playlists.
- Never ship to TestFlight or Play without Tony's separate confirmation.
- Keep Music playback settings isolated from TifloLector.
- Source selection is always explicit; storage connections do not imply full-library scans.
- No cloud secrets or account tokens in backups.

## Review Focus

- A source file moved or renamed: catalog preserves playlist references and shows an unavailable source until relinked (Task 1).
- Same track in two providers: retain distinct sources and allow deduplication without source deletion (Task 1).
- Playlist includes unavailable cloud music: queue skips with accessible reason, not a crash (Task 4).
- User revokes cloud credentials during playback: transition to unavailable and preserve library metadata (Task 6).
- Restore over modified library: offer merge/replace and never delete originals (Task 7).
